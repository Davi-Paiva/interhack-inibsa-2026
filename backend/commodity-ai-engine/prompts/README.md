# Commodity AI Engine Prompts

This folder contains the definitive prompts for the 5 Commodity AI Engine modules.

Important context:
- Feature engineering is treated as an existing dependency and must be reused.
- Do not rebuild feature engineering inside the modeling components.
- Components must consume feature tables generated by `backend/data_processing/features.py`.
- Schema source of truth is the Excel file at `backend/data_processing/inibsa_feature_tables.xlsx`.
- Any mismatch between assumptions and parquet columns must be resolved in favor of the Excel schema.

Mandatory first step for each component:
1. Load and inspect `backend/data_processing/inibsa_feature_tables.xlsx`.
2. Confirm expected table/column names for that component.
3. Validate parquet schemas against Excel before modeling logic.

Feature tables expected from data processing:
- `client_features.parquet`
- `product_features.parquet`
- `client_product_features.parquet`

Expected location pattern:
- `backend/processed_data/<mode>/features/`
- where `<mode>` is `historical` or `daily`

If your branch stores processed data in a different base folder, keep the same `<mode>/features/` contract and resolve the path in a single helper function.

## Prompt files

1. `PROMPT_1_KMEANS_CLUSTERING.md`
2. `PROMPT_2_CONSUMPTION_FORECAST.md`
3. `PROMPT_3_DEMAND_LEAKAGE.md`
4. `PROMPT_4_CAPTURE_SCORING.md`
5. `PROMPT_5_NEXT_PURCHASE.md`

## Usage order

Use prompts in order 1 -> 5. Each component depends on outputs from the previous ones.

## Hard constraints for all prompts

- Reuse cleaned + feature parquet outputs.
- Keep architecture modular and lightweight.
- Use pandas + sklearn/lightgbm only where required.
- No deep learning, no embeddings, no graph features.
- No outlier removal.
- Campaign periods are business context, not anomalies.
- Keep functions short and readable.

## Module contracts

Component 1 output:
- `cluster_assignments.parquet`
- `cluster_profiles.parquet`

Component 2 output:
- `consumption_forecast.parquet`

Component 3 output:
- `demand_leakage_signals.parquet`

Component 4 output:
- `capture_opportunities.parquet`

Component 5 output:
- `next_purchase_predictions.parquet`

All outputs should be written under:
- `backend/commodity-ai-engine/output/<mode>/`

## Shared key conventions

- Prefer identifiers already present in parquet tables.
- Build joins using stable keys only.
- Keep date columns as timezone-naive UTC-like pandas timestamps unless project conventions say otherwise.
- Always sort by date before rolling/window calculations.
- Avoid hidden global state. Pass mode and paths explicitly.
